この文書は、アプリの課題構成についての議論の記録。

## 1. 現在のアプリ

ホーム画面には次の3課題がある。

- **呼称**: 絵を見てことばを言う
- **選択**: ことばに合う絵を選ぶ
- **線つなぎ**: ことばと絵を線でつなぐ

設定画面では課題、問題数、親密度、カテゴリなどを組み合わせられる。選択課題はお題を「文字」「音声のみ（聴理解）」「文字＋音声」から選べる。教材は名詞、動作絵、情景絵を含む全176件。

運用上、**ホーム画面と設定画面は主にSTが操作し、患者さんは訓練画面を見る**。

## 2. 現在感じている問題

機能が増え、異なる分類軸が同じ階層で扱われている。

| 項目 | 本来の性質 |
|---|---|
| 呼称 | 訓練目的 |
| 聴理解 | 訓練目的／提示方法 |
| 選択 | 回答方法 |
| 線つなぎ | 回答方法 |
| 動作 | 教材の種類 |
| 情景 | 教材の種類／課題レベル |

例えば「選択」は、文字を見て選ぶ場合と音声を聞いて選ぶ場合で訓練目的が異なる。「情景」も、呼称側では情景説明、選択側では短文の聴理解になる。そのため、設定の組み合わせだけを見ると「何の能力を訓練しているか」が分かりにくくなってきた。

## 3. 一度合意した6つの臨床的な課題単位

課題の内容自体は、次の6つに整理しても違和感はない。

### 表出

- 名詞呼称
- 動作呼称
- 情景説明

### 聴理解

- 単語の聴理解
- 短文の聴理解

### 読字理解

- 文字と絵の対応

情景説明は単純な○／×ではなく、STが **「自立／手がかりあり／困難」** の3段階で記録する方針案に合意した。模範文を必要時に表示できるようにする。

## 4. 当初案とその懸念

当初は、ホーム画面に上記6課題をすべて並べ、選択した課題に必要な設定だけを表示する案を検討した。

しかし、この案は分類は整う一方で、次のような**現在のアプリの良さを損なう可能性**があると指摘された。

- 「呼称・選択・線つなぎ」の3つで全体を把握できる
- 少ない画面ですぐ開始できる
- 同じ操作に慣れたまま教材を変えられる
- カテゴリ、問題数、親密度などをSTが自由に組み合わせられる

そのため、**6課題で現在の3課題をそのまま置き換える案は未確定**。

## 5. 現在有力な折衷案（未確定）

ホームの3つの入口と自由度を残し、6つの課題単位をその下のプリセットとして整理する。

```text
話す
├─ 名詞呼称
├─ 動作呼称
└─ 情景説明

選ぶ
├─ 文字を見て絵を選ぶ
├─ 単語を聞いて絵を選ぶ
└─ 文を聞いて情景絵を選ぶ

つなぐ
└─ 文字と絵を線でつなぐ
```

考え方は次のとおり。

- 現在の3入口を「操作・反応形式」の軸として統一する
- 上位の「呼称」は、情景説明も包含できるよう「話す」等へ変更する案がある
- 現在の設定値を初期化する「プリセット」として6課題を用意する
- プリセット選択後も、STは問題数、難易度、カテゴリなどを変更できる
- 通常は分かりやすい初期値だけを見せ、現在の柔軟な組み合わせは「詳細設定」として残す案がある
- 不自然または成立しない組み合わせのみ自動で防ぐ

この折衷案もまだ決定ではない。特に「現在の良さ」が何かをもう少し言語化してから決める。

## 6. 課題ごとの想定設定（議論用）

| 課題 | 教材 | 提示・回答 | 評価 |
|---|---|---|---|
| 名詞呼称 | 名詞カテゴリ | 絵を見て発話 | STが○／×、ヒント使用、時間切れ |
| 動作呼称 | 動作絵 | 絵を見て発話 | STが○／×、ヒント使用、時間切れ |
| 情景説明 | 情景絵 | 絵を文で説明 | 自立／手がかりあり／困難 |
| 単語の聴理解 | 名詞・動作 | 音声を聞いて絵を選択 | 初回正答率、誤選択数 |
| 短文の聴理解 | 対になる情景絵 | 文を聞いて絵を選択 | 初回正答率、誤選択数 |
| 文字と絵の対応 | 名詞・動作 | 1問ずつ選択／複数を線つなぎ | 初回正答率 |

## 6.5 決定事項（2026-09-04 の議論）

- **現在の良さ**（守るもの）: 開始までが速い（2画面）、患者が見る画面が単純、同じ操作で教材だけ変えられる、STが自由に組み合わせられる
- **ホームの3入口は残し、名前を「話す / 選ぶ / つなぐ」に変更**（情景説明を「呼称」に含める違和感を解消。臨床用語はプリセット名で使う）
- **6課題はホームの各入口の下にプリセットとして並べる**（話す: 名詞呼称・動作呼称・情景説明 / 選ぶ: 文字を見て絵を選ぶ・単語を聞いて絵を選ぶ・文を聞いて情景絵を選ぶ / つなぐ: 文字と絵を線でつなぐ）。プリセットをタップすると、その課題用の初期値で設定画面が開く
- **情景説明の評価は「自立 / 手がかりあり / 困難」の3ボタンをSTが手動で押す**。模範文の表示と評価は切り離す（患者に見せるために開いた場合も記録されないように）
- **設定画面の「基本 / 詳細」分割は未決定**。問題数スライダーの良さを失いたくないため、静的モックアップで「詳細を折りたたみ＋現在値を1行表示」案と「見出しで分けるだけ」案を比べてから決める

## 7. 次のPCで話し合うこと

以下の順で議論する。コード変更はその後。

1. **現在のアプリの良さを言語化する**

4. **「基本設定」と「詳細設定」の範囲を決める**
5. **情景説明の3段階評価の操作と結果表示を決める**

7. **紙上または静的な画面案で確認してから実装する**

## 8. 次のセッションへの注意

- この議論に基づくアプリ本体のUI変更はまだ行っていない
- 既存の呼称・選択・線つなぎの機能はすべて動作しているので、保持しながら再編する
- ST向けの設定効率と、患者さんが見る訓練画面の単純さは別々に考える
- プリセット導入の目的は自由度を失くすことではなく、「何の訓練か」を明確にすること
